# Расписание учебной группы

Рабочий прототип по согласованным макетам: вход, регистрация, восстановление пароля, календарь месяца/недели/списка, фильтр дисциплин и подробности занятия. На компьютере правая панель всегда занимает одинаковое место. На телефоне по умолчанию открывается список, а подробности отображаются в отдельном окне.

## Запуск

Нужен Node.js 22.12+ (либо совместимая версия 20.19+).

```sh
npm install
npm run dev
```

Откройте адрес, который напечатает Vite. Без настроек Supabase нажмите «Открыть демоверсию». Тестовое расписание формируется для текущего и соседних месяцев. Имена вымышлены, ссылки на занятия и записи отсутствуют. Демо сохраняет только флаг входа в sessionStorage; пароли не сохраняются, аккаунты не создаются.

```sh
npm run build
npm run preview
```

## Настоящая регистрация и база

1. Создайте проект Supabase и выполните `supabase/schema.sql` в SQL Editor **один раз**. Для тестовых занятий дополнительно выполните `supabase/seed.sql`.
2. Создайте `.env.local` по образцу `.env.example`. Укажите адрес проекта и клиентский publishable/anon key в `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Ключ `service_role` или secret key в браузере использовать нельзя.
3. В Supabase Authentication включите Email/Password. В URL Configuration задайте Site URL и разрешённые Redirect URLs, например `http://127.0.0.1:5173`. Для размещённой версии укажите её адрес.
4. Перезапустите приложение. Зарегистрируйте аккаунт и подтвердите почту, если подтверждение включено. Восстановление пароля отправляет письмо и позволяет задать новый пароль после перехода по ссылке.
5. Координатор добавляет и редактирует занятия в Table Editor Supabase. Студенты могут только читать занятия своей группы. Отдельной админки в этой версии нет.

В первой версии регистрация открыта: каждый новый аккаунт автоматически входит в единственную группу МИСТ-25-3-1. Для закрытой группы или нескольких групп нужен следующий этап с приглашениями и проверкой членства. Выбор группы сейчас содержит только одну группу.

Время хранится в базе с часовым поясом и отображается в часовом поясе устройства пользователя. Тестовые SQL-занятия заданы в UTC+05.

Реальная авторизация требует вашего проекта Supabase; без подключения используется только демоверсия. Настоящие запросы к базе при ошибке не подменяются тестовыми данными.

## Проверка интерфейса

При запущенном локальном сервере и без настроек Supabase (проверяется автономная демоверсия):

```sh
npx playwright install chromium
npm run test:e2e
```

По умолчанию проверяется `http://127.0.0.1:5173`. Можно задать переменную `APP_URL`. Проверки покрывают демовход, выбор/закрытие занятия, стабильность сетки, переключение видов и месяцев, фильтрацию, выход, регистрацию и мобильное окно. Скриншоты сохраняются в `artifacts/`.

## Стек и структура

React, TypeScript, Vite, CSS Modules, Lucide, FullCalendar 6, Supabase JS 2. Версии фиксируются в `package-lock.json`.

- `src/components/Auth.tsx`: формы и запросы авторизации.
- `src/components/Schedule.tsx`: календарь и загрузка занятий.
- `src/components/LessonDetails.tsx`: подробности и мобильное окно.
- `src/demo.ts`: демонстрационные занятия.
- `supabase/`: таблицы, права доступа и начальные данные.

Проверено локально: сборка и сценарии интерфейса. Запросы к настоящему Supabase, отправка писем и SQL-политики требуют проверки после подключения вашего проекта.
